# 数据质量体系

解蹇数据底座的质量由三道关卡保证，任何一条数据入库前必须通过前两关，
且不破坏第三关（基准回归）。

## 第一关：真实求解验证

- 每条修复记录必须**重新提交求解器求解**（非静态检查）；
- 只有求解完成（COMPLETED）的案例才获得 `verified: true` 质量标签；
- 验证失败（FAILED）的案例保留并标记，用于诊断能力的负样本。

## 第二关：一致性校验

- 大模型生成的诊断报告与判案层事实逐条对账：
  - 单元-自由度矛盾（2D 单元却建议约束转动自由度）；
  - 约束 DOF 越界（报告提到不存在的自由度）；
  - 与判案结论矛盾（判案判定存在刚体模态，报告却称约束完备）；
- 矛盾即标记 error，需人工复核后方可入库。

## 第三关：基准回归

- 判案规则（标注器）的任何变更，触发 17 案例全量回归；
- 漏报、误报双零才允许上线——**标注器的每一次更新都有版本可追溯**。

## 反馈闭环

用户对每份诊断的"准 / 不准"评价回流至案例，形成 RLHF 式偏好数据，
持续校准诊断与标注质量。
